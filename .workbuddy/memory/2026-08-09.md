## 第二轮全面审计（用户要求"再认真检查一遍"）
写了 Node 脚本批量采样 48 条曲线（每条 1000 个采样点 + t=0/0.25/0.5/0.75/1 关键点），新增发现并修复：

- **quad / cubic / quart / quint 的 `outin` 第一分支**都因为运算符优先级漏了括号，导致 `f(0)=0.5` 而非 0，曲线起点错误。第一轮我只看了 `back.outin` 和 `expo.outin`，漏了这 4 条。
  - 改前：`1 - (1 - 2 * t) * (1 - 2 * t) / 2`
  - 改后：`(1 - (1 - 2 * t) * (1 - 2 * t)) / 2`
- **`spring.in` 公式语义写反**：`f(0)=1, f(1)=0`，曲线方向与 in 缓动相反。改为 `1 - out(1-t)` 后正常。
- **描述文本重复**：标题栏已经显示 `EASE_IN_OUT` 等，描述区又拼了一次 `缓入缓出 — ...`，重复展示。已清理 `easeDescs` 去掉前缀。

- 教训：抽样审查（spot check）容易漏，尤其是同一类公式（quad/cubic/quart/quint 是同一模式被复制 4 遍，任一处错都该一起错，但 `outin` 那一遍恰好都没复制对）。下次类似审计应**先写一个 batch 验证脚本**而不是逐条肉眼看。

## 第三轮：删 dead CSS + SPRING 负数答疑（用户追问）
- 删除 CSS 死代码：颜色兜底选择器 `[style*="color: #1f2328/#57606a/#8c959f"]`（仅存在于注释，无任何内联 style 匹配）与 `div[style*="border: 1px solid"]`（line 72 的 `border:1px solid` 是 CSS 规则而非内联 style，故属性选择器匹配不到）。CSS 区已干净。
- 解答用户两个疑问：
  1. **TRANS_SPRING + EASE_IN 为何 value 负数**：spring 的 out 形式会 overshoot 超过 1（阻尼余弦近似与真实 Godot 都是），而 EASE_IN = `1 - out(1-t)`，把末端的 overshoot 镜像成起点的 undershoot（<0）。这是 spring 缓动的本质，真实 Godot 同样会出负数，**不是 bug**。
  2. **替换为真实 Godot TRANS_SPRING 源码能否兼容网页端**：能。公式是纯 exp/cos/π 数学，JS/Canvas 完全可移植，不会崩溃；页面 canvas 对越界值只是裁剪（主曲线溢出 [0,1] 网格框、演示小球沿轨道左右 overshoot），当前自定义 spring 本就越界，故换真实源码不会引入新问题，仅振荡次数/阻尼形状不同。
  - 注意：本次未能在线拉到 Godot 4.3+ 合并后的确切 spring 公式与默认参数（raw.githubusercontent 对该工具连续 404；可查镜像 commit 562bc… 为 4.3 前旧版，interpolaters 表仅 11 种且无 spring）。若要真正替换，需先取到确切源码（含默认 frequency/damping），再实现并加 y 轴自适应缩放让 overshoot 在框内美观呈现。
